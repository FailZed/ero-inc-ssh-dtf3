# Импорт учебной модели из macOS-сборки

`tools/import_live2d_mac.py` читает повседневную модель `interaction_model` из
предоставленной пользователем Unity-сборки в `.app`. Проверен на локальной сборке
из `~/Downloads/factorial-omega-mac-64` (Unity 6000.3.8f1), macOS Apple Silicon.
Intel Mac отдельно не проверен.

## Запуск

Команды выполняются в терминале из корня EroInc. Нужен Python 3.11 или новее.
Скрипт использует соседний `import_mdrg_study_models.py`, профиль взаимодействий
EroInc и библиотеку Cubism из `addons/gd_cubism/bin`. Отдельно от репозитория
одного файла скрипта недостаточно.

```sh
cd /Users/vladzvezdin/GoDot/ero-inc
python3 -m venv .cache/live2d-research-venv
.cache/live2d-research-venv/bin/python -m pip install -r tools/requirements-live2d-import.txt
.cache/live2d-research-venv/bin/python tools/import_live2d_mac.py
```

Пути по умолчанию:

- Источник: `~/Downloads/factorial-omega-mac-64`.
- Результат: `~/Downloads/live2d-study/mac-interaction`.

Папка результата должна отсутствовать. Скрипт не перезаписывает готовый экспорт.
Для повторного запуска выбери новое имя:

```sh
.cache/live2d-research-venv/bin/python tools/import_live2d_mac.py \
  --target "$HOME/Downloads/live2d-study/mac-interaction-2"
```

Произвольный путь к приложению или содержащей его папке:

```sh
.cache/live2d-research-venv/bin/python tools/import_live2d_mac.py \
  --source "$HOME/Downloads/factorial-omega-mac-64/My Dystopian Robot Girlfriend.app" \
  --target "$HOME/Downloads/live2d-study/my-copy"
```

`--inspect` проверяет чтение модели без экспорта. `--core` задаёт совместимую
библиотеку, экспортирующую C API Cubism Core. По умолчанию используется уже
установленный модуль нашего проекта; библиотека из чужого `.app` не загружается.

## Как открыть результат

В EroInc: **Мастерская → Настройки → Загрузить профиль… → workshop.profile.json**.
Это загружает модель с одеждой, привязками головы, щеки, рук и корпуса,
морганием и взглядом из существующего профиля EroInc. Доступны ползунки
параметров, переключение физики и запись собственных движений.

Голый файл `.model3.json` тоже можно открыть через «Открыть модель…», но
такой способ не применяет профиль EroInc и его начальные значения.

## Что получено

- `interaction_model.moc3` — скомпилированная модель.
- `texture_00.png` и остальные атласы — текстуры в порядке индексов Cubism.
- `interaction_model.physics3.json` — преобразованная физика Unity Cubism.
- `interaction_model.model3.json` — связи ресурсов и доступные группы параметров.
- `model.info.json` — параметры, сетки, части, источник и контрольные суммы.
- `workshop.profile.json` — существующие привязки EroInc с путём к новой модели.

Проверенный экспорт: 106 параметров, 257 сеток, 3 текстуры, 11 цепочек физики.
Модель и профиль загружены отдельным headless-процессом Godot; проверены
пять зон и наличие назначенных им параметров. Это проверка загрузки, а не
подтверждение полного совпадения поведения с исходной игрой.

Скрипт не переносит постановочные модели, код игры, диалоги, контроллеры Unity
или их анимации. Он не создаёт редактируемый исходник `.cmo3`.
Существующий каталог моделей EroInc, сохранения и исходное приложение не меняются.

Папку готовой модели можно переносить в другой проект целиком, сохраняя
вложенность. В `.model3.json` пути относительные. В `workshop.profile.json`
поле `model.model` содержит абсолютный путь: после перемещения папки обнови его.

Другие версии игры могут иметь иную структуру объектов или внешние ссылки.
В таком случае скрипт сообщает об ошибке вместо создания неполного комплекта.

## Отдельная мастерская без игры

В `~/Downloads/live2d-study` подготовлен самостоятельный проект. На Mac открой
`Запустить Live2D.command` двойным щелчком. Он сразу показывает учебную модель.
Для Windows x64 рядом есть `Start Live2D.bat` и комплект движка/библиотек;
этот отдельный комплект проверен запуском на macOS, Windows-запуск здесь не проверялся.

В `workshop` находятся только модель и инструменты мастерской. В `runtime` —
копия движка. Для запуска не нужны основной репозиторий, Python или интернет.
Профили и записи на Mac находятся в
`~/Library/Application Support/Live2D-study/character_workshop`.
Журналы и проверенный снимок окна — в `logs` рядом с запуском.

Воспроизводимая сборка в новую папку:

```sh
python3 tools/build_live2d_study.py \
  --destination "$HOME/Downloads/live2d-study-new" \
  --model "$HOME/Downloads/live2d-study/mac-interaction" \
  --windows
```

Для сборки нужны уже установленные в `.cache/runtime` движки. Убери `--windows`,
если нужен только Mac. Существующие компоненты мастерской скрипт не перезаписывает.
Проверено: загрузка 106 параметров, отдельные пользовательские данные, отсутствие
игровых autoload, запись/воспроизведение движения, сохранение/загрузка профиля
и отображение модели с нативным OpenGL-рендерером на Mac.
