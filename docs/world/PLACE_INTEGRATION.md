## Существующий атомарный контракт

Использованы прочитанные `scripts/mechanics/actions.gd`, `events.gd`,

`gameplay/action_policy.gd`, `guided_story.gd` и текущие `scene_hotspots.gd` /
`gameplay_shell.gd`. Новый runner и отдельный сервис не нужны.

В `catalogue_patch.actions` лежат две обычные записи текущего каталога:

| Действие | Условия | Время и результат |
| --- | --- | --- |
| `wp_last_crate` | `south_trade_street`, 08:00–22:00, не больше одного подтверждения в день | `actions.perform`, 2 минуты, пустые costs/effects; никаких покупок, пополнения склада и наград |
| `wp_rain_margin` | `riverside_cafe_front`, дождь, флаг ещё не равен true | `actions.perform`, 2 минуты; единственный эффект `flag city_cafe_notice_sheltered=true` |

Обе сценки теперь самостоятельные действия героя. Они не изображают разговор
с несуществующим продавцом или посетителем. Сверение покупок не резервирует
товар; игрок выбирает настоящую сделку в существующем магазине. Защита афиши —
не помощь всем NPC сразу и не увеличение отношений.

`Actions.execute("perform")` проверяет доступность, ведёт существующий дневной
счётчик, применяет эффекты и расходует минуты внутри `Simulation.command`.
Ошибка внешней транзакции откатывает состояние и RNG. Helper не вызывает
эти методы и не меняет их порядок. Нет цепочки из двух внешних команд
`clock.advance` и `world.flag`: такая цепочка не была бы одной транзакцией.

`Events.fire` **не расходует поле minutes** и не нужен для этих двух действий.
Не надо дополнительно вызывать его после `actions.perform`: это создало бы
второй независимый исход. У пакета нет нового квеста, `ready_event` или
дополнительного сохранённого журнала. Если позже потребуется отдельное
журнальное событие, его условие/фиксацию следует добавить в уже существующую
успешную транзакцию отдельным назначенным этапом, а не из UI после команды.

### Единственная новая сохраняемая реакция

`world.flags.city_cafe_notice_sheltered` — обычный флаг, который записывает
эффект `wp_rain_margin`. Существующий snapshot сохраняет `world.flags` вместе
с миром. Новый контейнер состояния, миграция и пользовательское редактирование
слота не требуются. Отсутствующий флаг означает, что герой ещё этого не делал;
второй раз действие недоступно по `not flag=true`. На повторном осмотре
`notice_case` выбирается строка об уже защищённой афише даже после окончания
дождя. Это чтение, без минут, награды и второй записи эффекта.

Стандартные дневные `counters` обоих действий остаются внутренней частью
существующего сервиса. Они не являются новым состоянием сюжетной реакции.
Изменение каталога меняет его hash; не вводить поддержку прежнего каталога
или преобразование пользовательских сохранений ради этого пакета.

## Чистый helper и переданный контекст

Helper `city_place_content.gd` extends `RefCounted`, не имеет lifecycle,
цикла симуляции, UI, сохранения, RNG и мутаций. Он читает JSON, проверяет
ссылки, возвращает копии описаний и доступность из текущего контекста.

- `read_file()` → `Rules.ok({content: ...})` либо явная ошибка чтения/JSON.
- `validate(content, graph, catalog)` → пустая строка или первая ошибка.
  Проверяются реальные адреса, публичность сцен, строки, координаты, команды,
  конфликт каталога и ровно один допустимый флаговый эффект.
- `catalogue_actions(content)` → глубокая копия двух обычных definitions.
- `describe(content, location_id, context)` → заголовок, описание и предметы.
- `inspect(content, location_id, object_id, context)` → бесплатный текст и
  варианты с доступностью/длительностью; ни одна команда не выполняется.
- `choice(...)` → заново проверенный descriptor выбранного варианта.
- `result_text(content, action_id)` → строка для показа **после успешной**
  существующей команды, не дополнительный эффект.

Ожидаемый контекст:

```gdscript
{
    "phase": Gameplay.phase,
    "state": sim.state, # helper только читает
    "access": {
        location_id: CityGraph.can_enter(graph, location_id, actor,
            int(sim.state.clock.minute_of_day), int(sim.state.clock.weekday))
    },
    "availability": {
        "actions.perform:wp_last_crate": sim.services.actions.availability("wp_last_crate"),
        "actions.perform:wp_rain_margin": sim.services.actions.availability("wp_rain_margin"),
        "world.journey:pharmacy_house": sim.services.world.route("pharmacy_house"),
        # Остальные видимые переходы вычисляются тем же world.route.
        "shop:market": market_access_result
    }
}
```

`actor` создаётся доверенным bridge нового графа: не брать привилегии/право
входа из пользовательского `args`. `market_access_result` — `Rules.ok()`
или `Rules.fail(...)` после проверки **текущих** catalog.shops.market.location,
часов и доступности торговой операции; наличие NPC не подменяет магазин.
Root переносит market с прежнего `global_map` на `south_trade_street`
одновременно с потребителями. Отсутствующий authority result блокирует
выбор, а не разрешает его по умолчанию. Это явный контракт передаваемых
данных для UI, без поддержки прежних систем.

Минуты перехода берутся из `world.route(...).data.minutes`; минуты малого
действия — из `actions.availability(...).data.minutes` с проверкой совпадения
с подготовленным definition. Helper не хранит маршрут и не пишет часы.
Для открытия магазина `time_source=none`: просмотр 0 минут, сделка отдельно.
Ни лавка, ни наблюдение не вызывают `needs.leisure`; его действующая цена
30 минут не превращается в фиктивный пятиминутный отдых.

1. **`scripts/gameplay/main_simulation.gd::_init`**, после единого применения
   готового нового графа и обновлённых мест магазинов/работ, до итоговой

2. **`scripts/ui/gameplay/gameplay_shell.gd::_place`**: получить свежий контекст,
   вызвать `describe` для одной из четырёх сцен и добавить её предметы через
   уже существующий `SceneHotspots.add_action`. Их callback открывает
   существующую компактную предметную панель с результатом `inspect`.
   Координаты согласует UI-исполнитель с настоящим фоном; отдельный UI не нужен.
3. **Та же предметная панель → `_context_action` / `_act` → `Gameplay.execute`**:
   перед подтверждением снова получить `choice`; затем передать его
   `module/operation/args` в существующую команду. `kind=catalogue` только
   открывает уже существующую торговлю. Не исполнять data effects в UI,
   не отправлять команду при бесплатном `inspect`, повторно проверить после
   очереди/перехода времени. После успеха можно показать `result_text`.
4. **`Gameplay.changed` → существующий `_queue_refresh` / `_refresh`**:
   перестроить descriptor по новому состоянию. После загрузки обычного snapshot
   `inspect` сразу читает флаг; специальный hook чтения сохранений не требуется.

Пункты2–4 изменяют один существующий UI-поток и выполняются после окончания
параллельного UI-этапа. Пролог остаётся в `guided_story`; helper требует
`phase=free_roam` и не переигрывает сцену зеркала или детские воспоминания.

### API предметного компонента

`PlaceObjects` extends `VBoxContainer`, не создаёт окно/runner и не вызывает
Simulation или Gameplay. Показывает четыре объекта текущего места (16 по
четырём местам) в компактном селекторе и бесплатное описание. Переключение
объекта и `update` не меняют переданное состояние мира.

- `setup(content, locale="ru")`, `supports(location_id)`, `update(context)`;
- `select_object(id)`, `selected_object_id()` для восстановления UI-выбора;
- `selection_changed(location_id, object_id)` для сохранения этого выбора
  в существующем `_screen_state` при пересоздании `_body`;
- `action_requested(module_id, operation, args)` — только две разрешённые
  `actions.perform`, никогда не прямой флаг, clock или выдача наград;
- `selected_choice_descriptor()` — копия последнего проверенного выбора
  с `label`, `confirmation`, `minutes`, `command`, `location_id`, `object_id`.
  Shell показывает единственное подтверждение по этому descriptor.

`world.journey` и люди не дублируются внутри компонента: остаются у обычных
выходов/списка людей Shell. Закрытый зал кафе и продуктовая лавка показываются
недоступными по фактическому authority result. Новый граф поместил магазин
в `south_market`; уличный объект не совершает покупку снаружи. Аптека остаётся
публичным фасадом без выдуманного торгового сервиса и доступа в квартиры.

В кандидатском JSON оба `pending_route` удалены: `campus_park_gate` и
`south_promenade` теперь указаны конкретными существующими адресами с запросом
настоящего маршрута. `Content.authority_keys(content,location_id)` перечисляет
нужные запросы для свежего контекста. Фиксация реакций по-прежнему только в
существующем `actions.perform`; компонент читает флаг повторного визита.
