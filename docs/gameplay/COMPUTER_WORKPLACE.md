# Компьютер как рабочее место

Реализовано 28 октября 2026 в основной симуляции (`main_schema = 11`). Данные — `data/mechanics/computer.json`, логика — `scripts/mechanics/computer.gd`. Изменения UI выполняет отдельный агент. Все команды отправляются через `Gameplay.execute("computer", operation, args)`; для отрисовки использовать чистый `Gameplay.sim.services.computer.inspect()`. Не вызывать `execute` сервиса напрямую: общий диспетчер обеспечивает откат, проверку занятости, нужды и сохранения.

## Рабочий стол

`inspect()` возвращает `blocked`, `busy`, три профессиональных `tracks`, `board`, `projects`, `portfolio`, `upgrades`, `specializations`, `lessons`, `formats`, `sponsors`, `topics`, `operations`, текущие `hack`/`broadcast`, историю `broadcasts`/`history`, общих `followers` и `trace`. У улучшений, уроков и спонсоров есть `available` (собственные условия; общие `blocked`/`busy` проверять отдельно), у спонсоров — `next_available`. Темы содержат действующие `modifiers`, профессии — `next_level_xp` (0 на максимальном уровне).

Работа требует компьютера в оборудовании и спальни действующего дома. Отказ: `missing_computer`, `computer_desk_required`, `no_current_home`. Активные операция/эфир блокируют начало другой компьютерной работы; обычное закрытие окна не отменяет сессию. Отдельные команды остановки доступны и вне дома. Время, наличные, навыки, аудитория, след и дневные лимиты общие с остальной игрой.

Предлагаемые разделы экрана: «Заказы», «Безопасность», «Эфир», «Обучение», «Рабочее место». При активной сессии показывать её текущий этап и явную кнопку завершения/отмены. Сроки отображать по игровому календарю. Причину недоступности и ожидаемую длительность показывать до действия. `computer.duration(operation,args)` возвращает длительность с учётом оборудования.

## Программист

Ежедневная доска содержит три предложения из шести типов: страница мастерской, регистрация мероприятия, каталог архива, клубный планировщик, городской портал, учебное приложение. ID предложения имеет вид `day:slot`; не подставлять вместо него тип проекта. Порог навыка виден в предложении. Одновременно допускаются три активных заказа; срок — три игровых дня.

| Команда | Аргументы | Результат |
| --- | --- | --- |
| `take_project` | `{id: offer.id}` | Принять доступный заказ |
| `project_step` | `{id, step, choice}` | Выполнить текущий этап |
| `revise_project` | `{id}` | Исправить результат после трёх этапов, до двух раз |
| `deliver_project` | `{id}` | Сдать готовую работу, получить оплату и запись в портфолио |
| `abandon_project` | `{id}` | Закрыть заказ без оплаты |

Этапы: `design` → `build` → `test` → `delivery`. Выборы берутся из `project.choices`; их `minutes`/`energy` уже учитывают процессор. Нельзя повторять уже завершённый этап. Быстрый путь экономит время, оставляет замечания и обычно требует доработки. Приёмка: качество не ниже 60, замечаний не больше одного. Оплата зависит от качества и количества доработок. Просроченные заказы закрываются автоматически. `project.ready` — готовность к сдаче; также доступны `can_revise`, `estimated_pay`, `remaining_minutes`. Планировщик показывает близкие сроки и готовность к сдаче.

## Хакер / специалист по безопасности

Список целей и подходов: `computer.inspect().operations`; отдельный прогноз — `digital.preview(id, approach)`. Сохраняются существующие легальные/рискованные цели, фильтр криминального контента и последствия: след, штрафы, внимание служб, интервалы между попытками.

- `hack_start {id: operation_id}` — 15 минут, подготовить отчёт; возвращает `data.token`.
- `hack_step {token, step, choice, approach}` — три этапа с индексами 0..2. Тексты — `inspect().hack.scenario`, выборы — `hack.choices`; `choice`: `careful`, `balanced`, `fast`. `approach` на последнем этапе задаёт темп финальной операции, те же три значения, по умолчанию `balanced`.
- `hack_abort {token}` — остановить, сохранив уже потраченное время и накопленный след.

Подготовка повышает шанс, спешка повышает давление; рискованные шаги оставляют след до финала. Итог использует единственную существующую цифровую проверку. Срок отчёта — 24 часа; нельзя начать шаг, который вместе с завершением выйдет за срок. UI показывает шанс как вероятность, не гарантию.

## Стример

- `stream_start {id: topic_id, format, segments, sponsor}`. `segments` — 2..6 блоков по 15 минут, по умолчанию 4. Подготовка — 10 минут. `format`: `focused`, `community`, `showcase` (последний требует портфолио). `sponsor` необязателен, пустая строка — без партнёра.
- `stream_step {token, step, choice}`. Текущий индекс и событие — `inspect().broadcast`; варианты `content`, `chat`, `moderate`, `stabilize`. Последний блок автоматически завершает эфир.
- `stream_finish {token}` — завершить досрочно; доход и подписчики за проведённые блоки сохраняются, спонсор за незавершённый эфир не платит.
- `publish_highlight {id: broadcast.id}` — 20 минут, один ролик из завершённого эфира качества от 40, дополнительные подписчики.

События меняют полезность действий. Публичная модель содержит только текущее событие, без будущего расписания и правильного ответа. Формат, оборудование и специализация влияют на качество/вовлечённость. Повтор одной темы за сутки уменьшает приток аудитории. Спонсору нужны аудитория, завершённый эфир и среднее качество; после завершённой спонсорской трансляции действует недельный перерыв. Заброшенная сессия закрывается через восемь часов, сохраняя проведённые блоки. История ограничена 48 записями.

## Рост и оборудование

- `lesson {id}` — 30 минут: +10 профильного навыка, +12 профессионального опыта; каждый курс доступен раз в игровой день.
- `specialize {id}` — со второго профессионального уровня: первая специализация бесплатна, смена — 60 ¤. По две ветви у программиста, хакера и стримера.
- `upgrade {id}` — 20 минут, три уровня у `processor`, `network`, `studio`. Процессор сокращает время программирования на 8% за уровень; сеть улучшает операции и эфир; студия повышает качество эфира. Цена следующего уровня — базовая цена × номер уровня.

В существующий список работ добавлены `junior_developer` и `broadcast_host` с содержательными рабочими ситуациями; всего работ 35. Их завершение развивает соответствующий компьютерный путь. Существующие цифровые контракты, операции и быстрые эфиры используют ту же профессиональную прогрессию, оборудование и аудиторию.

## Обработка команд и проверка

После успешной команды заново читать `inspect()`. Не начислять деньги, опыт, аудиторию или прогресс задания из UI: это уже сделано симуляцией. Показывать `data.description`, когда оно есть. `stale_computer_session`/`stale_computer_step` означают устаревший экран: обновить данные; повторная выплата исключена. Невыполнимая команда откатывается целиком, включая время и RNG.

Основные отказы: `computer_session_active`, `computer_project_unavailable`, `computer_project_capacity`, `computer_skill_required`, `computer_project_needs_revision`, `computer_deadline_too_close`, `computer_revision_unavailable`, `computer_report_too_old`, `computer_portfolio_required`, `computer_sponsor_unavailable`, `computer_highlight_unavailable`, `computer_lesson_daily_limit`, `computer_level_required`, `insufficient_energy`, `insufficient_funds`. Общие конфликты работы/учёбы проходят через `ActionPolicy`; пропуск занятий требует обычного явного выбора `skip_classes`.

Проверки 28 октября 2026: `python3 tools/test_mechanics_depth.py` — 160 проверок, 0 ошибок; `pwsh -NoProfile -File tools/test_mechanics.ps1 -Isolated -Pack` — 2674 проверки, 0 ошибок. Тесты проверяют этапы, оплату, последствия отмены, сроки, общую аудиторию, новые профессии, повтор с сохранённым RNG, откат неудавшегося действия и отказ повреждённым сохранениям. Сдача проекта и улучшение оборудования связаны с целями задания «Дом под свой образ жизни»; промежуточный этап проект не засчитывает. Поддержка старой схемы и переписывание пользовательских сохранений не добавляются. Это проверка логики, не подтверждение готовности отдельного UI-экрана.
