## Наблюдения в запущенной School

28 октября осмотрено окно School на парковом фоне. Это исследование UX; донорские тексты, изображения и код в runtime EroInc не переносятся.

- Переключение людей и действий сохраняет сцену и положение одной узкой панели справа. В списке людей сразу видны имена и занятость.
- Список действий зависит от места. В парке доступны короткий отдых, физическое занятие и сон на скамье; ожидание и поиск человека находятся рядом. Наблюдалось наличие пунктов, их выполнение не проверялось.
- Выбор человека открывает отдельное представление разговора с категориями. Закрытие возвращает к прежней панели людей. Каталог разговора EroInc принадлежит соседнему исполнителю.
- Рюкзак — плотный список с количеством и весом. Выбор вещи меняет описание в постоянной нижней области; большой отдельный предпросмотр не требуется. Нажатие на заголовок меняет порядок списка.
- Осматривались обычные карточки предметов без их использования или удаления. Предметы не использовались и не удалялись; сохранения вручную не загружались и не перезаписывались.

Для авторов мест: разделять «что делать здесь», «кто находится рядом» и «куда выйти» внутри одной устойчивой точки взаимодействия. Содержательность места задают полезные повторяемые действия и посетители, а не количество меток. Для парка назначение скамьи связано с отдыхом/сном, дорожек — с физической активностью. Для внутренних помещений должны быть собственные действия и условия доступности вещей. Это выводы для дизайна; новую географию не предлагал и не подключал.

## Текущий результат

- Убрана растровая тяжёлая рамка окон; единая прозрачная сине-чёрная поверхность с тонкой линией. Исправлено повторное умножение цвета в city_light, из-за которого фон был слишком тёмным.
- Восстановлены лёгкие нижние иконки и верхние время/деньги. Сохранён Android-телефон.
- После нового уточнения пользователя постоянные пространственные точки заменены одной компактной панелью «Действия / Люди / Места». Все старые полезные команды сохраняются внутри неё.
- Сумка заменена компактным списком без пятнадцати пустых ячеек и большого рисунка. Действия только для выбранной вещи, экипировка/снятие и установка используют текущие сервисы.

## Клавиатура — подключено и закончено

По прямому поручению пользователя согласовано с координатором подключение Tab. Координатор разрешил ровно одну строку в original Shell; она добавлена рядом с resized.connect:
`_scene_actions.navigation_changed.connect(_wire_scene_focus)`

Это рабочий путь основного интерфейса. Временный `--wire-navigation-hook` полностью удалён из runner; тест больше не подключает сигнал самостоятельно. Координатор сообщил, что передаст ту же строку geography для isolated candidate, чтобы будущее сведение сохранило Tab. Сам candidate не редактировал.

Что исправлено для игрока:

- После смены вкладки список больше не оставляет удалённые пути Tab/стрелок: scene_interaction уведомляет существующий общий пересчёт фокуса после раскладки новых строк.
- Стрелки соединяют вкладки и список; Tab/Shift+Tab проходят через список и остальные элементы HUD. Свёрнутые строки пропускаются; после раскрытия навигация восстанавливается.
- В сумке вправо можно перейти от вещи к её действию, влево вернуться к выбранной вещи. Порядок Tab соединяет поиск, селекторы, строки и действия, сохраняя выход к Back/HUD. Пустой поиск не оставляет ссылки на удалённую строку.
- Длинное имя при125% не расширяет компактное окно: в строке многоточие, полное имя в описании/подсказке. Селекторы имеют input_id, прежние item_id/gameplay_action сохранены.
- Esc из списка категорий, расход ровно одного предмета, экипировка/снятие и возврат выбранной вещи были правильными; эти действия проверены без лишних замен логики.
