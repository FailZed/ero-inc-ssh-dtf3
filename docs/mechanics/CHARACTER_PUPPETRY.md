# Интерактивные персонажи Live2D

27 октября 2026. В EroInc подключён настоящий рендер Live2D Cubism и собственная
мастерская управления персонажем. Вход: **главное меню / меню паузы → Мастерская**.
Прямой запуск из корня проекта:

```powershell
.\tools\open_character_rig.ps1
```

Это действующая сцена основного проекта, доступная также отдельно. Старые
запускаемые прототипы `hybrid_rig` и `layered_rig` заменены; их внешние результаты
подготовки арта остаются исследовательскими материалами на E:.

для переделки самой топологии/рига нужен исходный проект или собственный риг.

## Что можно делать в мастерской

- Тянуть голову, щёку, руки и корпус повседневной модели. Проверка попадания
  использует актуальные треугольники деформированных сеток. Специальные HitArea
  работают и при прозрачном отображении. Авторский порядок зон даёт небольшим
  областям головы и рук приоритет перед корпусом; внутри зоны учитывается порядок
  отрисовки.
- Отпускать мышь за пределами сцены, отменять захват клавишей Esc и безопасно
  переключать модели. Второй Esc закрывает мастерскую. В настройках доступен
  захват по щелчку; обычный режим требует удержания кнопки.
- Выбирать три комплекта одежды, выражения и позы повседневной модели. Это наши
  пресеты параметров, одежда уже встроена в исходный риг. Начальный показ — одетый.
- Менять все параметры с учётом собственных min/max/default модели, искать их по
  имени, управлять непрозрачностью частей во вкладке «Слои», менять палитру.
- Включать физику, взгляд и моргание, выбирать сглаживание, чувствительность и
  масштаб. Поддерживаются мышь и события касания.
- Записывать движение, воспроизводить его с интерполяцией и зацикливать. Запись
  хранит параметры примерно с частотой 30 Гц; физика вычисляется при показе.
  Повторное сглаживание при воспроизведении не применяется.
- Сохранять/загружать JSON профиля и движения. Собственные файлы по умолчанию
  лежат в `user://character_workshop/`; игровые слоты и их схема не используются.

У пяти постановочных моделей доступны рендер, родная физика, параметры, части,
профили и запись. Подробный профиль захвата сейчас создан для `interaction_model`.
Это описанный ниже объём реализации, а не заявление о полном паритете всех сцен,
реакций и игровых правил MDRG.

## Как менять поведение

Основной файл — `data/characters/interaction_profile.json`. Значения находятся в
родных диапазонах Cubism. Например, у этой модели `ParamEyeOpen` имеет диапазон
**−1…0**, где 0 означает открытый глаз; жесты рук **1…3**. Универсальное правило
«все параметры от 0 до 1» здесь неприменимо.

Пример зоны захвата:

```json
{
  "id": "head",
  "title": "Голова",
  "meshes": ["HitAreaHeadpat"],
  "x": "ParamHeadX",
  "y": "ParamHeadY",
  "press": {"ParamHeadpat": 1},
  "move_x": "ParamHeadpatX",
  "move_y": "ParamHeadpatY"
}
```

`x`/`y` управляют смещением относительно точки захвата; `move_x`/`move_y` —
скоростью движения курсора. `press` действует до отпускания. `meshes` принимает
маски имён, например `AttachArmLHand*`. Сначала проверяются верхние зоны списка.
Имена сеток и параметры перечислены в `model.info.json`.

В профиле есть `initial`, `gaze`, `blink`, `zones`, `expressions`, `poses`,
`outfits`, `parts`, `palette`. Для индивидуального варианта сохрани профиль из
мастерской, отредактируй его `bindings` и загрузи обратно. Профиль также содержит
путь к модели, текущие значения параметров, непрозрачность частей и настройки
сглаживания. Внешние `.model3.json` открываются кнопкой «Открыть модель…»;
для них привязки задаются в собственном профиле. Требуется совместимая с Core 5.0
модель. Обычный PNG/PSD сначала нужно подготовить и привязать в редакторе рига.

Параметрами владеет `scripts/characters/parameter_bank.gd`. Источники смешиваются
по приоритетам: начальный гардероб 5, взгляд 10, поза 20, краткая реакция 30,
выражение/наряд 40, моргание 50, мышь 60, ручное изменение 100, запись 200.
Снятие источника возвращает управление нижнему слою. После смешивания действуют
ограничения и плавное, линейное либо пружинное движение.

`interaction_memory.gd` хранит короткую историю удержаний и состояние показа
(`idle`, `attentive`, `surprised`, `comfortable`). Это отдельное состояние
представления персонажа; игровые отношения и прогресс NPC обслуживаются основными
сервисами EroInc. Компонент `puppet_view.gd` посылает `interaction_started` и
`interaction_finished`, к которым можно подключать игровые действия.

## Runtime и ресурсы

Рендерер: [gd_cubism v0.9.1](https://github.com/MizunagiKB/gd_cubism/tree/v0.9.1),
Godot 4.7.2, Cubism Native SDK 5-r.1, Core 5.0 из указанной установки. Собрана
GDExtension **Windows x64**. Локальная правка привязки открывает `is_initialized()`;
сборка использует MinGW import library для Core DLL. Происхождение и лицензии —
`addons/gd_cubism/`. Исходники, компилятор и кэш находятся в
`E:/Ai/ComfyUI-EroInc/runtime/cubism/`. SHA256 архива llvm-mingw проверяется сборщиком.

Генерация изображений и обучение LoRA для этого набора не нужны. Исходные PNG
занимают около **42 МиБ**, весь учебный набор с метаданными — около **48 МиБ**.
Одновременно загружается одна модель. Три RGBA8-атласа 4096² без mipmap занимают
**192 МиБ** до учёта масок, сеток и памяти движка; это расчёт текстур, не замер
всей VRAM. Снимок мастерской сохраняет рядом `.metrics.json` с показателями Godot.
Второй ПК для обычного использования мастерской не требуется.

Windows preset включает каталоги JSON/MOC и нативную библиотеку. Android preset
исключает этот Windows-модуль и учебный набор; кнопка мастерской там отключена.
Для мобильного Live2D потребуется отдельная сборка Core/GDExtension под Android.

Для собранного Windows EXE есть прямой вход:

```powershell
EroInc.exe --audio-driver Dummy -- --character-workshop
```

Проверенная debug-сборка находится в
`E:/Ai/ComfyUI-EroInc/runtime/cubism/main-build/`. Реальный кадр из этого EXE —
`E:/Ai/ComfyUI-EroInc/runtime/cubism/main-build-workshop.png`; он просмотрен.
В этом запуске Godot сообщил около **302 МиБ** общей видеопамяти процесса и
**141 МиБ** своей статической памяти. Последнее не является полным RSS процесса.

Импорт и сборка при необходимости повторяются Python из исследовательского venv:

```powershell
$py = 'E:/GoDot/.research/mdrg-0.97.12/tools/venv/Scripts/python.exe'
& $py tools/import_mdrg_study_models.py
& $py tools/build_cubism_runtime.py
```

## Проверка

```powershell
.\tools\test_characters.ps1
.\tools\test_characters.ps1 -Visible
.\tools\test_characters.ps1 -Pack
.\tools\godot.ps1 --headless --script res://tests/characters/integration.gd --quit-after 300
.\tools\test_mechanics.ps1 -Isolated -Pack
.\tools\open_character_rig.ps1 -Capture E:/Ai/ComfyUI-EroInc/runtime/cubism/workshop.png
```

Тестовый проект персонажей имеет отдельный user:// и проверяет реальные MOC.
Упакованный тест запускается без распакованных моделей; две DLL находятся снаружи
PCK, поскольку их загружает ОС. Матрица фактических проверок и ограничения находятся
в `CHARACTER_PUPPETRY_VERIFICATION.json`. Снимки — реальные кадры мастерской Godot,
не сгенерированные визуальные референсы.

Пройдено 76 проверок модуля в headless, OpenGL и PCK, по 9 проверок подключения
к меню исходного и упакованного основного проекта, 4 проверки исключения модуля
из Android-ресурсов и 2607 проверок изолированного PCK механик. Реальный Windows
EXE также открыл мастерскую и записал просмотренный кадр. APK на устройстве в
этом проходе не проверялся.

Изолированные тесты персонажей завершаются без сообщений об утечках. При выходе
основной игры остаются ранее наблюдавшиеся предупреждения дополнений о ресурсах:
63 объекта / 27 ресурсов при запуске редакторским бинарником, 61 / 26 в debug EXE.
Их устранение не входит в этот модуль. Подробный исследовательский аудит MDRG
хранится в `E:/GoDot/.research/mdrg-0.97.12/MDRG_AUDIT.txt`.
