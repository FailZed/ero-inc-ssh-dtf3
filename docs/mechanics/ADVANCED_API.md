# Контракты механик второго–четвёртого этапов

Все изменения выполняются через `simulation.command(module, operation, args)`.
Ответ имеет `ok` и `data` либо `error`. Перед представлением результата нужно
проверять `ok`: отказ не расходует ресурсы и не меняет RNG. Примеры ниже —
независимые последовательности; у каждой указаны предпосылки.

```gdscript
const Simulation = preload("res://scripts/mechanics/simulation.gd")
var simulation = Simulation.new(42)
```

Команда — логическое действие. Runtime не меняет сцены, не открывает диалог,
не обращается к серверам и не пишет в слоты сохранения. Для событий подписаться
на `domain_event`; следующие команды из обработчиков ставить через
`call_deferred`, поскольку во время уведомлений действует защита повторного входа.

## Бой

Нужен существующий NPC в текущей локации с ненулевым здоровьем.

```gdscript
simulation.command("social", "generate", {"id": "opponent"})
simulation.command("combat", "start", {"npc": "opponent"})
var preview = simulation.services.combat.forecast("jab", "body")
simulation.command("combat", "action", {
    "action": "attack", "move": "jab", "part": "body", "power": 1.0
})
simulation.command("combat", "action", {"action": "guard", "part": "head"})
simulation.command("combat", "action", {"action": "end_turn"})
```

`forecast` возвращает `accuracy`, `damage`, `critical`, `ap`, `stamina` и
`injury_multiplier`. `damage` — ожидаемый базовый урон до броска критического
попадания и защиты цели; это не обещание снятых HP. Вероятности находятся в [0, 1].

Действия: `attack`, `guard`, `stance` (`id`: balanced/defensive/aggressive),
`recover`, `intimidate`, `escape`, `end_turn`. Смена стойки стоит 1 AP, удар
расходует AP и выносливость, нулевые AP передают ход. Противник расходует 4 AP
в несколько действий по доступности оружия, AP и выносливости. Базовые расчёты
и отличия от School описаны в [FORMULAS.md](FORMULAS.md).

Приёмы: jab, heavy, kick, feint, body_hook, uppercut, sweep, disarm, slash,
thrust, bat_precise, bat_swing. Оружие нужно заранее приобрести и надеть через
`inventory.equip`. Классы: unarmed, knuckles, blade, blunt. В модели есть также
профили spiked_knuckles и folding_blade. Зоны: head/body/arms/legs.

Активный бой разрешает только боевые команды. Завершение и награда однократные;
раны NPC/игрока остаются после боя. Старые команды `encounters.combat_start` и
`encounters.combat_action` делегируют тому же сервису.

## Здоровье и состояния

| Команда | Аргументы и результат |
| --- | --- |
| `health.diagnose` | `target` по умолчанию player; возвращает здоровье, раны и медицинское состояние |
| `health.treat` | `id`: bandage/medicine/clinic, `target`; расходник или стоимость, время, cooldown |
| `health.intoxicate` | `amount`: 1..100, `target`; интоксикация влияет на эффективные характеристики и спадает по часам |
| `health.prenatal_care` | `target` с активным состоянием pregnancy; 30 денег, 30 минут, пауза минимум 1440 минут |
| `lifecycle.start` | `id`, `target`, необязательный `partner`; запускает определение из conditions |
| `lifecycle.remove` | `id`, `target`; снимает состояние и его внешние признаки |

Бинт останавливает кровотечение, препарат уменьшает игровую инфекцию, клиника
включает период восстановления. Краткое лечение сохраняет уже назначенный
длительный уход. Старый `character.treat` теперь идёт через клинику и её cooldown.
Базовые характеристики не переписываются при травмах: читать
`services.character.effective_stat(id)`.

В `conditions` можно задать `duration`/`stages[].after` в минутах или
`duration_months`/`stages[].after_months` по настоящему календарю. Границы
рассчитываются при старте, обрабатываются при перемотке и публикуют
`condition_stage`/`condition_completed`. Пример pregnancy использует девять
месяцев; `appearance.pregnancy_stage` — токен для будущего представления.
Окончание создаёт одну запись в `healthcare.family`. Последующие семейные
сюжеты и взросление в этот контракт не входят.

## Работа, заказы, стриминг и журналистика

```gdscript
# Нужен компьютер в world.equipment.
simulation.command("careers", "take_contract", {"id": "small_website"})
simulation.command("careers", "work_contract", {"id": "small_website", "minutes": 120})
simulation.command("careers", "claim_contract", {"id": "small_website"})
simulation.command("careers", "stream", {"id": "education", "minutes": 60})
```

`work_contract` принимает 1..240 минут, списывает фактически нужное время и
проверяет завершение до дедлайна. Требования берутся из каталога: профессия,
уровень, навык, оборудование и декларативные условия. Завершённая заявка
оплачивается только по `claim_contract`; состояние хранит качество и claimed.
Просроченная активная заявка становится failed. Определения заказов однократные;
новые заказы получают новые ID в каталоге.

`careers.shift {id}` учитывает место/часы/энергию/суточный предел и профессиональный
XP. Профессии: digital, retail, journalism. Темы `stream`: games, education,
creative; длительность 15..240 минут, общий предел 360 минут в сутки.
Отчёты стримов ограничены последними 64 записями.

Для материала: `investigate {id}` → `interview {id, npc}` → `verify {id}` →
`publish {id}`. Начало даёт один источник исследования; интервьюируемые должны
быть разными и находиться рядом. Число источников задаётся `sources`. Повторная
проверка не оплачивает материал; повторная публикация запрещена. Запрос
`services.careers.publication_capacity()` возвращает вместимость незавершённых
материалов; пороги `professions.journalism.publication_slots_at` равны
[0, 3, 8, 15, 30]. Публикация освобождает слот.

## Социальные правила

| Команда social_rules | Предпосылки и эффект |
| --- | --- |
| `biography {id}` | Структура биографии, черты личности, описание; без временных затрат |
| `ask_history {id}` | NPC рядом, доверие ≥10, усталость <90; 5 минут, память, бонус только при первом раскрытии |
| `apologize {id}` | NPC рядом, новый неприятный эпизод или ещё не обсуждённое недоверие; один раз в сутки, 5 минут |
| `partner {id}` | Взаимное влечение, доверие/привязанность/интерес, отсутствие других партнёров, окончание паузы после расставания |
| `breakup {id}` | Существующая пара, изменение доверия/отношения, пауза 7 суток |
| `date {id,venue?}` | NPC свободен и рядом, взаимная совместимость, доверие, энергия и отсутствие высокого страха; coffee/walk/cinema, пауза 24 часа |
| `promise {id, promise}` | Обещание из каталога, свой срок; второй активный экземпляр с тем же ключом запрещён |
| `fulfill {id, promise}` | Реальное выполнение условий, однократный бонус; просрочка обрабатывается часами |
| `gathering {candidates}` | 2..6 уникальных гостей рядом с доверием ≥10; по порции meal на гостя, энергия ≥10, один раз в сутки, 90 минут |

`services.social_rules.compatibility(a, b)` возвращает взаимность и оценку;
`conversation_forecast(id, action)` — шанс, усталость, повторения и вклад памяти;
`describe(id)` — самостоятельно сформированный текст из фактов. NPC создаются
взрослыми (минимум 18). В шаблоне доступны gender, attracted_to, cohort, traits,
education, occupation, family, combat_style, weapon и inventory.

Автономные отношения обновляются в 18:00 игровых суток. Лояльность ограничивает
риск предательства; события меняют память и отношения, не запускают сцены.
`preferences.content_tag {id:"romance", enabled:false}` запрещает романтические
действия и образование пар; betrayal отдельно выключает риск предательства.
Разговор учитывает свежие события за сутки и штраф повторения темы.

`interactions.<id>.branches` — упорядоченный список словарей с `id`, `when`,
необязательными `chance_bias`, `success`, `failure`, `text_token`. Первая
совпавшая ветвь накладывает свои поля на базовый исход действия. Контекст
содержит `npc`, `relation` и обычные разделы состояния; `player` здесь остаётся
игроком. `conversation_forecast` и `social.interact` возвращают branch и
text_token. В `parity.json`: discuss_books, offer_help, joke. В `balance.json`
добавлены listen, share_interest, flirt и set_boundary. Флирт проверяет фильтр
romance и взаимную привлекательность; повтор уменьшает положительную награду.
Подарки передают предмет всегда, но бонус после третьего за сутки обнуляется.
Подробные зависимости и варианты свиданий — в [BALANCE.md](BALANCE.md).

## Коллективы

Сначала `organizations.create`, `recruit` и `assign`. Далее:

```gdscript
simulation.command("institutions", "policy", {
    "id": "creative_collective", "focus": "festival", "wage": 10
})
simulation.command("institutions", "campaign", {
    "id": "creative_collective", "campaign": "festival"
})
```

Фокусы: balanced/research/publicity/festival; зарплата на участника 0..100.
Раз в сутки зарплата переводится из бюджета, недостаток денег снижает мораль
и публикует `club_wages_unpaid`. Производительность зависит от здоровья,
ответственности, морали и оборудования; `install {id, item}` переносит предмет
из инвентаря игрока в коллектив. Кампания проходит стадии с переносом избытка
усилия; `claim_campaign {id, campaign}` оплачивается один раз.

Выборы: `election {id, candidates:[...]}` → `vote {id,npc,candidate}` →
`resolve_election {id}`. Нужно минимум два разных действующих участника,
один голос на участника. При равенстве выбирается первый ID в сортировке.
Изменение состава отменяет активные выборы (`club_election_cancelled`), после
чего их можно назначить заново. Выборы — дополнительное правило EroInc.

## Жильё и интерьер

```gdscript
# Нужны средства на квартиру и предмет desk в инвентаре.
simulation.command("housing", "buy", {"id": "apartment"})
simulation.command("housing", "move_in", {"id": "apartment"})
simulation.command("housing", "furnish", {"id": "apartment", "item": "desk"})
simulation.command("interior", "place", {
    "id": "apartment", "item": "desk", "x": 1, "y": 2, "rotated": false
})
var plan = simulation.services.interior.render_plan("apartment")
```

Команды `place` и `move` задают абсолютную клетку; `unplace` снимает с плана,
сохраняя оборудование, `remove` возвращает предмет в инвентарь с проверкой веса.
`properties.room_size` задаёт сетку (по умолчанию 8×6), `furniture.size` — размеры,
layer и visual — порядок и ID представления. Пересечения запрещены независимо
от слоя. Сейчас один экземпляр каждого вида мебели на объект недвижимости,
как и в существующем контракте `housing.furnish`; складывание предметов на стол
и несколько одинаковых стульев потребуют расширения адресации экземпляров.

Визуальная лаборатория: `res://scenes/debug/interior_lab.tscn`, F6. Графику
School она не использует. Заселение `housing.tenant {id,npc}` меняет домашнюю
локацию NPC, `remove_tenant` возвращает прежнюю.

## Скрытность и мини-игры

`security.steal {npc,item?}` использует деньги или реальный предмет цели.
`security.burglary` — вероятностный вариант с отмычкой в доме цели.
`security.begin_burglary` — тот же контекст с интерактивной машиной замка;
дальше подавать `encounters.game_input {value:0|1|2}`. Результат однократно
передаёт предмет/деньги или начисляет штраф. `pay_fine` расходует деньги,
`serve_sentence` — игровое время. Это абстрактные игровые правила.

```gdscript
simulation.command("encounters", "game_start", {
    "type": "pushups", "required_reps": 5, "duration_ms": 30000
})
# Передавать абсолютные миллисекунды с начала упражнения, а не дельту кадра.
simulation.command("encounters", "game_input", {"elapsed_ms": 250})
simulation.command("encounters", "game_input", {"elapsed_ms": 500})
```

`timing` — вращающееся окно попадания, `pushups` — усилие со спадом между
нажатиями. Вход elapsed_ms монотонен, нажатия чаще 100 мс отклоняются,
длительность 1000..60000 мс, число повторений 1..50. Даже без нажатий будущий
экран должен прислать финальный input на границе duration_ms для завершения
таймера. Время не привязано к частоте кадров; приёмка воспроизводима в headless.
После завершения идут игровые минуты и однократный XP. Пока мини-игра активна,
runtime принимает только `game_input`.

Режимы blackjack/reaction/strength/guess/lockpick сохранены. `guess` — числовая
задача EroInc; источник School `mods/system/guess.rpy` исследован как встречи
с гостями, которые реализованы отдельной командой `social_rules.gathering`.

## Программы обучения

`activities.practice {id}`: strength/running/reading/speech/cinema. Стоимость,
место, требования, длительность и дневной предел задаются training_programs.
В начале 100 единиц тренировочного XP дают пункт базовой характеристики до cap;
выше значения 10 порог плавно растёт как `100 + 12d + 0.2d²`, `d = stat - 10`.
Остаток сохраняется; skill XP передаётся обычной системе опыта. Пример чтения
требует книгу, физические программы ограничивают дневную нагрузку.

## Внешность и гардероб

`appearance.customize {target?,features:{...}}` меняет собственные косметические
параметры персонажа; строки являются ID/значениями для будущего представления,
не путями загружаемых файлов. Вложенные исполняемые структуры не допускаются.
Служебные признаки состояния, включая pregnancy_stage, менять этой командой
нельзя. `gender`, если передан, — male/female/nonbinary; для NPC он синхронизирован
с социальным профилем. Значения остальных особенностей согласует будущий портрет.

`morphology`: human / semi_furry / furry. Неизвестная категория отклоняется.
В дескрипторе `anatomy` возвращает face (human/muzzle), covering (skin/fur),
animal_ears и tail. Полуфурри сохраняет человеческое лицо/кожу. `has_tail`
задаётся булевым параметром отдельно: по умолчанию у полуфурри хвоста нет,
у полного фурри есть. Это позволяет не противоречить сценарию Лиры. Дескриптор
не загружает изображения и не изменяет характеристики из-за внешнего вида.

`appearance.outfit {target?,id}` надевает полный комплект только при владении
всеми его предметами. `equip {target?,id}` / `unequip {target?,slot}` работают
и для игрока, и для NPC. Для игрока они используют существующий инвентарь.
Предмет NPC можно сначала передать через social.gift; владение не возникает
от выбора визуального токена. Требования предмета проверяются в контексте
надевающего персонажа (`player` в предикате означает этого персонажа).

`outfits` содержит комплекты, их предметы и необязательные условия activities,
locations, weather. Шаблон NPC задаёт wardrobe — ID комплектов; принадлежащая
начальная одежда создаётся вместе с NPC. При смене расписания NPC выбирает
подходящий доступный комплект, запасной — первый полный комплект гардероба.
Украденная одежда не восстанавливается автоматически. Пустой wardrobe разрешён.
Примеры: casual/work/training; графика для этих ID в основную игру не добавлялась.

`services.appearance.descriptor(target)` возвращает независимую копию параметров
и equipment со слотами, item и visual. Он подходит будущему рендереру портретов
и не зависит от системы слоёв Godot. Проверенные контракты не означают наличие
всех донорских моделей тела, волос, одежды или визуальных комбинаций.

## Генерация мира и решения NPC

```gdscript
simulation.command("population", "configure", {"values": {
    "count": 40, "age_min": 22, "age_max": 45,
    "female_ratio": 0.5, "semi_furry_ratio": 0.25, "furry_ratio": 0.15,
    "stat_min": 3, "stat_max": 12, "sociability": 55,
    "trait_spread": 30, "activity_mode": "mixed"
}})
var batch = simulation.command("population", "generate")
# При успехе: data.ids, data.count, data.morphologies.
```

`configure` заменяет настройки пакета, дополняя переданные поля значениями
по умолчанию; уже существующие NPC не меняются. `generate` добавляет пакет.
Размер 1..200, суммарный предел 500 NPC. Возраст 18..80, минимум не выше
максимума; характеристики 1..100, шесть средних черт 0..100, разброс 0..100.
Доли 0..1; доля людей равна `1 - semi_furry_ratio - furry_ratio`. Сумма двух
заданных долей не превышает 1. Число NPC по категориям определяется методом
наибольших остатков, поэтому сумма всегда равна размеру пакета. Точность
процентов ограничена числом жителей. Это настройки случайных NPC, не сюжетного каста.

Пол и категория внешности перемешиваются с RNG симуляции. Имена/возраст,
характеристики/черты, рабочая или учебная роль, биография, расписание и одежда
создаются из собственных шаблонов. Каталог не меняется. `mixed` выбирает роль
работника с вероятностью 0.6; `work`/`study` задают однородный ритм. Морфология
сама не даёт поведенческих или числовых бонусов.

Новый `npc_behavior` не требует команд из UI. Он отдаёт `plan`, доступные
`candidates` и часовые последствия. Срочное здоровье, сон и еда приоритетнее
обычного расписания; обязательная работа/учёба приоритетнее досуга. Декларативные
условия занятий и мест проверяются в контексте самого NPC. Для свободных занятий
доступны роли и веса черт. Еда расходует meal либо 5 денег; при бедности действует
самостоятельная ветвь общественного питания. Доход и XP идут за текущее занятие.

В 18:00 знакомый может прислать входящее сообщение при доверии ≥20,
общительности ≥60, здоровье ≥20 и усталости <80; вероятность 0.35.
`npc_message_received` сообщает ID сообщения и NPC. Это пример собственного
социального события, не полная таблица входящих School.

## Пользовательская сложность и частные последствия

```gdscript
simulation.command("preferences", "customize", {"values": {
    "xp": 1.1, "relation_gain": 1.2, "injury_damage": 0.5,
    "initial_points": 30, "satiety_enabled": true,
    "exhaustion_enabled": false, "eviction_enabled": true
}})
var hunger_enabled = simulation.services.preferences.rule("satiety_enabled", true)
```

Команда включает custom, объединяет новые значения с прежними custom.
Остальные ключи берутся из профиля custom каталога. `difficulty {id}` выбирает
easy/normal/hard/custom. Диапазоны и булевы ключи определены в
`preferences.gd`; неизвестный ключ, неверный тип или нечисловое значение отклоняются.
Изменение `initial_points` в ходе симуляции не выдаёт игроку новых очков;
этот параметр читает конфигуратор начального профиля.

`world.appeal` требует отчисления, выполненной домашней работы и денег.
Успех снимает отчисление/предупреждение и сбрасывает пропуски, расходует 30 минут.
`housing.pay_arrears {id}` гасит весь долг и разрешает повторное заселение;
после выселения новый расчётный месяц начинается от оплаты. Обморок запрещает
обычные команды, пока не пройдёт восстановление; доступны часы и отдых.
Подробные коэффициенты и отличие баланса от School — в `FORMULAS.md`.

## Конфигуратор для изолированной приёмки

```gdscript
const Setup = preload("res://scripts/mechanics/setup_config.gd")
var config = Setup.defaults()
config.population.count = 40
var check = Setup.validate(config)
var preview = Setup.build(config) # Только после проверки preview.ok читать data.
# data.simulation — отдельный runtime, data.profile — копия профиля.
```

Возраст профиля 18..80, девять стартовых атрибутов 5..30, расходы считаются
сверх базовых 5; остаток 40/30/20 или initial_points остаётся свободными очками.
Конфигуратор проверяет имя, диапазоны и бюджет до создания. Лаборатория
`world_setup.tscn` использует этот API и выдаёт `setup_confirmed`; сигнал никуда
в основной игре не подключён. Полный стартовый конфиг здесь нужен для теста.
Продуктовый поток должен сохранить выбор мира до пролога и применить профиль
позднее у зеркала. Эта интеграция, как и запись параметров в сохранения, отложена.

## Границы подключения

Используются только `scripts/mechanics`, `data/mechanics` и отладочные сцены.
Сервис не должен вызывать GameSession, Dialogic или Save напрямую. Готовый
адаптер первого этапа не активирован и во втором–четвёртом этапах не менялся. Будущая
интеграция выбирает представление, сцены, каталог EroInc и владение временем.
