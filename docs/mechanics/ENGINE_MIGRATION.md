# Godot 4.7.2 — переход 18 октября 2026

Обновление разрешено владельцем проекта в ходе четвёртого этапа. Закреплена
стабильная **4.7.2**, revision `ed1daf0bf`. Версия 4.8 пока beta и не выбрана.
[Официальный архив](https://godotengine.org/download/archive/),
[изменения совместимости 4.6 → 4.7](https://docs.godotengine.org/en/stable/tutorials/migrating/upgrading_to_godot_4.7.html).

## Установка и запуск

Windows x64 сборка установлена параллельно:
`C:/Users/vladi/AppData/Local/Programs/Godot/4.7.2/`.
Предыдущая 4.6.3 не удалена. `.godot-version` закрепляет patch-версию,
`project.godot` отмечает features 4.7, `tools/test_mechanics.ps1` использует
новую сборку. Запуск редактора: `powershell -File tools/godot.ps1`.
Произвольные CLI-параметры можно передавать тому же скрипту.

Из официального `Godot_v4.7.2-stable_export_templates.tpz` установлены шаблоны
Windows x64 debug/release и Android debug/release/source в
`%APPDATA%/Godot/export_templates/4.7.2.stable`. Шаблоны других платформ
не распакованы. SHA256 архива проверен:
`f298490b8d44d934be425a5a65a51bf15f422428b229a06a6e11d9ffea248011`.

Источник редактора — официальный репозиторий `godotengine/godot-builds`,
release `4.7.2-stable`. SHA256 скачанного архива
`Godot_v4.7.2-stable_win64.exe.zip` проверен по digest release asset:
`731980f9608d61333e5baf54a2ef17210acc7a538446c0cb9969f002aca1e953`.

## Совместимость дополнений

Первый импорт обнаружил три отсутствовавших явных возврата в установленном
Dialogic `2.0-Alpha-20 WIP (Godot 4.4+)`. В 4.7 это мешает компиляции:

- `Modules/Variable/subsystem_variables.gd`: `_get` для отсутствующей переменной
  и вложенной папки теперь явно возвращает null.
- `Modules/Text/node_name_label.gd`: `_set` для необрабатываемого свойства
  явно возвращает false.

Это три завершающих return в двух файлах; успешные ветви и формат данных
не изменены. Подсистема сохранений Dialogic не редактировалась. Исходные файлы
сохранены вне проекта, в `../.research/school-0.981/phase4/before-dialogic-*`.
При будущем обновлении самого Dialogic проверить необходимость локальных правок.

Повторный editor import проходит без Parse Error / Compile Error. Отдельный
smoke-проход проверяет известные/неизвестные переменные, вложенные папки,
setter и создание главного меню с текущими autoload. Главное меню также
отрисовано через D3D12 Mobile на RX 7800 XT, снимок визуально проверен.

В основном проекте сохраняются предупреждение Quest Weaver о неподключённом
inventory_controller и 27 ресурсах дополнений при выходе. Godot 4.7.2 также
показывает 63 оставшихся ObjectDB instances; отсутствие утечек всего
основного проекта этой миграцией не утверждается. Изолированный runtime чист.

Android SDK build-tools в окружении недоступны, поэтому APK не собирался.
PCK тестового runtime экспортируется и проходит тот же набор отдельно от исходников.
Из установленного debug-шаблона также собран отдельный Windows EXE: 707 проверок
проходят при запуске самого бинарника. Для него только в минимальном проекте
создан Node-вариант того же тестового runner и временная стартовая сцена;
главная сцена EroInc не менялась. Файлы проверки находятся в phase4 вне проекта.
Полное прохождение пролога, все UI-состояния и устройства Android этой проверкой
не покрыты. Новые механики к текущему прохождению не подключены.

## Откат

Закрыть редактор, восстановить `phase4/before-project.godot` в корень проекта,
выбрать установленную 4.6.3 и вернуть `.godot-version`/пути запуска. Кэш `.godot`
генерируется заново старой версией; при необходимости безопаснее сначала
переименовать его в резервную папку, чем удалять. Локальные явные return допустимы
и в GDScript 4.6.3; исходные копии сохранены. Слоты и игровые данные пользователя
в процедуре миграции не преобразовывались.

Результаты тестов и хеши — [VERIFICATION.json](VERIFICATION.json).
